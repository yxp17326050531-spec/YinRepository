# 伊瑟对局助手维护规则

- 此目录为 PySide6 桌面程序，入口 app.py/qt_app.py；不要改成网站或每次重新打包交付。
- 在 main 分支持续维护，更新器依赖同一分支的可快进历史。不要改写已发布历史。
- 2.8.0用户B方胜利对照推翻382固定A胜/383固定B胜；原码与旧候选仅作诊断，未经确认的自动结果保持unknown。协议方向与己方身份分开；本场胜方、己方、昵称校正独立保存且可撤销，不覆盖原始记录或被重新导入清除。
- 0x6004结算仅按连接、精确记录与时间、上下文及无歧义生命周期关联；关联成功不等于胜方已确认。不要仅凭单份导出或改名文件把结果码硬编码为A/B胜方。
- 保留点击名字修改精确角色/皮肤 ID 映射、本场修正、历史多选删除与恢复。
- 2.10.0采用用户确认的v0草稿方向：紫黑底、青色强调、黄色速度、左右两队卡片；保留原生Qt，1050px起保持双队并排，较小窗口滚动兜底。UI_PREVIEW.png 为真实运行截图。
- 数据、日志、pcap、凭据、虚拟环境不得提交。内置名称只是默认值，用户映射必须优先。
- 运行 `QT_QPA_PLATFORM=offscreen python -m unittest discover -v`（Windows 可直接 python）；只增加行为回归，避免重复测试实现。
- 测试中的sqlite3连接必须显式close或使用contextlib.closing；连接本身的with仅提交/回滚，不关闭文件。写入夹具还须保留事务提交，避免Windows临时目录清理出现WinError 32。
- unittest先tearDown再执行addCleanup，后者按LIFO执行。临时目录删除必须排在额外Archive的日志关闭之后；有附加资源清理时，在setUp先注册目录清理，不能在tearDown提前删除目录。保留Windows日志锁模拟回归检查。
- 免费素材和依赖；额外付费预算为零。不要自动启用付费服务。

- 强化增量：0x1132 field3 按 UID 合并字段，0x1134 field2 为等级、field3 为 UID 列表；缺失字段不是零，保留已存矩阵/标志。离线回放不得使用时间更晚的库存作基础。
- 源器分类：同类筛选 OR，副属性 AND，类别之间 AND。未知稀有度/初始副属性条数不猜，手工分类与原始观测分开。

- 当前优先级：源器模块补齐属性数值排序后暂时搁置，保留已有功能；重心转向对局数据读取，不继续扩展强化规则分析。排序使用解码小数，缺失值在升降序均置后，不对速度强制舍入到格点。

- 对局生命周期按捕获连接隔离；本地记录ID不是协议对局ID。开场失败/流缺口/断开/结束须阻断旧场关联；重复或重叠开场歧义不猜胜负。未知编号的阵容候选仅用于诊断，不计正式对局。
- 对局详情保留上一场/下一场、全历史跳转与返回历史定位；跨分页跳过已删除记录，实时更新不得打断历史浏览。
- 主页面角色行直接显示生命/攻击/防御/速度和暴击率/暴击伤害/效果命中/效果抵抗；2.10.0分基础与增减伤两区显示全部十四项，普通窗口分别四列两排/三列两排，宽窗口展开八列/六列，包含PVP增伤/PVP减伤/额外减伤/无视防御/结果增伤/结果减伤，缺失显示—，0%及超过100%的观测值保留，不对已解码百分比再乘100。
- 已观测0x8421回放封装：field2.field2为双方阵容，复用实时属性解码。该消息不得覆盖本人会话的结算目标；不因采集结束改成缺结算。额外字段含义未确认，不猜胜负/技能/伤害；玩家账号元数据不复制到回放存档；2.7.0仅允许读取已观察到的昵称路径2.1.8.1.3，昵称和A/B对应未确认，不按列表顺序绑定。只提交合成协议夹具，不提交真实抓包或个人阵容。
- 2.10.1用户确认矩阵战斗效果1051=戍卫8、1121=奋进8、1151=收割8、1431=沸腾打击12。其他未知档位仍允许threshold为null并显示待确认。不把effects_raw的数组下标视为固定语义，不猜33/35等未知效果含义。
- 用户确认83889586为刻影“屠夫”，按刻影单独显示，不归为矩阵/智壳；戍防官、光执事等未知编号不猜。刻影仅占位，暂不扩展分析。
- 0x2961登录快照：field2为元件记录，field1为装配分组；元件按截图对照独立解码，低8位属性、8至15位元数据待确认、高16位以上数值；不套用源器解码。字段3为已对照专属类型，字段6标志1与锁定对应；缺失/零仍分开。专属加成仅用于已验证类型且装配引用匹配时，不修改基础值。完整消息验证后替换元件集合，旧缓存缺该类别显示未采集，缓存恢复保留元件与分组；未接入实时元件变更，不承诺最新状态。

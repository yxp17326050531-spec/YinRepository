## PVE 最小化 / 锁屏操作试验

本版仅发布到 `experiment/pve-background`，不合并main、不重新打包EXE。入口在设置页“主页『再来一次』后台点击试验”。这是固定坐标、固定等待时间的兼容性试验，不是已经验证可用的挂机成品。没有读取游戏内存、注入、驱动、前台鼠标输入或新增依赖。

先手动设置并开启游戏的连续战斗，回到游戏主页，保持窗口尺寸固定。选择游戏窗口，点“5秒后取鼠标位置”，把鼠标停在主页“再来一次”按钮中央，不必点击。只记录这个位置，坐标为游戏客户区位置，-1表示未设置。设置点击间隔，首次点击也会等待此间隔；间隔应覆盖你这一组连续战斗的耗时。默认180秒、最多3次点击、总时限10分钟。可停止、关闭试验窗口或助手停止，Ctrl+Alt+F8注册成功时也可停止。锁屏时热键不保证可用，仍受次数与总时限约束。

先在前台验证一次，再分别最小化、Windows锁屏测试。记录会标注最小化状态、锁屏/解锁通知和发送时间，可解锁后导出，最多保留最近500行。只显示“消息已发送，游戏响应待核实”，点击次数不当成完成副本数，不加入战绩。游戏是否接受消息、最小化或锁屏是否继续战斗需本机观察确认；游戏忽略窗口消息时，本版不能挂机。不识别按钮是否出现、结算、体力、断线或购买弹窗；这是定时点击而非图像识别，固定坐标可能误点，请先使用短时限并核对前台效果。睡眠不属于锁屏；执行超时10秒不补发积压点击。窗口/进程/客户区大小变化或发送失败会停止。

参考查看了 [WhiteFree22333/etheria-ai-assistant](https://github.com/WhiteFree22333/etheria-ai-assistant) 的窗口输入、截图与战斗公共流程，没有引入其源码、模板或重依赖。该项目的post_click会尝试SetForegroundWindow，截图也有前台回退，所以不能把其后台功能说明当成最小化/锁屏可用的证据。本试验保持不抢焦点，只简化为用户所需的单点重复操作。

## 历史性能、昵称查找与自动分类（2.11.0）

历史页改用SQL计数和分页，每页仅读取100场的轻量摘要；上下文批量关联查询，共用设置、模式和身份资料，不再逐场读取整份阵容并重复扫描参考记录。统计页使用角色编号摘要，不读取完整属性或结算载荷；隐藏时不重算，返回时复用结果，有数据变更再刷新。表格改为整批填充后计算一次列宽，删除记录只刷新对局相关界面。首次升级会为已有历史补建摘要，不改写原始数据。

在“历史与日志”输入玩家昵称，按回车或“查找战绩”，可按部分名字、完整`#编号`及类型筛选。列表显示双方昵称，查找统计覆盖所有匹配页，显示己方胜/负/平/未确认及已确认胜负样本的胜率；未知方向或结果不猜。支持手工校正后的昵称。

对局历史和自定义编号映射均支持Ctrl+左键、Shift多选后按Delete；快捷键只在相应表格获得焦点时生效，编辑文字不会误删记录。Ctrl+A选择当前页；“删除当前筛选全部记录”可跨页删除当前类型/昵称的匹配结果，适合清理PVE，并保留恢复最近一批删除。历史另支持“批量分类选中”，不改变本场身份、胜负校正与统计分组；选择“未分类”恢复自动规则。

按用户设定，3v3自动归GVG，非3v3/4v4自动归PVE。4v4须有本连接300秒内的确认选人，双方各至少两名独立角色与各自上场阵容唯一对应、与另一方无交集，才自动归BP排位；单纯收到一条选人消息不足以分类。旧记录中已保存双方选人/阵容对应证据的也会自动补分类，缺证据的4v4保留未分类。已有手动分类与回放/观战边界继续优先，4v4的已有模式映射按原规则处理；普通观战不因此计入本人战绩。

性能对照：同一Linux环境、3000场合成记录，旧版读取一页历史约1840ms，新版约3.9ms，昵称筛选一页约12ms；新版实际Qt历史页切换连同绘制约26ms，已加载的战绩页再次切换约5ms。数字是本地离屏测试结果，不代表Windows实机保证。源码通过update.cmd更新至2.11.0，未重新构建EXE。

验证：166项完整回归通过，包含SQL分页与有界查询、昵称字面匹配、手动名称优先、同连接选人/过期/预览判定、旧记录迁移、本人回放过滤、多选Delete焦点隔离、跨页筛选删除/恢复及隐藏统计缓存。

## 本号昵称与排位结算积分判定（2.10.4）

在“设置 → 我的游戏昵称”填写昵称并保存，推荐带游戏中的`#数字`后缀；省略后缀时要求本场唯一匹配。昵称必须已通过确认选人和上场阵容对应到A/B方向，不按左右位置或昵称排列顺序猜己方。保存后当前记录和历史显示立即重新计算，本场手动方向及胜方校正优先；清除本号身份会同时清除昵称。

实时排位及其原始pcap导入现在支持按积分自动判断胜方：开场与结算的BattleID、上下文及连接关联必须一致，结算前积分与段位须唯一对应开场玩家资料；同段位积分增加判该队胜，减少判对方胜。该规则由认输败局与正常胜局的对照建立，不把381/382/383固定解释为A/B胜。昵称用于确定己方，积分证据独立确定胜方。

双方积分相同、积分不变、升降段位、缺少资料/选人/结算、重复或冲突记录、回放/观战不自动推断。当前是有完整积分证据时的自动识别，不承诺覆盖所有模式。旧原始记录不改写；重新导入完整抓包可补充独立证据，已有手动校正保留。模式分类仍按现有已确认映射或手动分类处理。

继续使用源码目录update.cmd更新，重新启动后标题与侧栏显示2.10.4；本次不重新构建EXE。

验证：157项完整测试通过；真实正常胜局导入并填写本号昵称后，界面显示B方为己方、结算积分增加20、胜利。回归覆盖认输败局、A/B交换、重名、同分、保分、段位变化、编号不符、重复/冲突结算、观战、手动校正、重导入与重启。运行环境为Linux离屏Qt，未进行Windows实机验证。

点击“分类筛选”组合矩阵、矩阵点数、稀有度、初始副属性条数、主属性与副属性。同一类别可多选，副属性要求同时具备，不同类别同时生效。筛选条件会记住；“清除筛选”同时清空文字搜索。选中装备后，实时更新尽量保留同一 UID 的选择，详情可继续查看原始 JSON。

属性按已对照样本拆分：`数值 = raw >> 12`，`属性编号 = (raw >> 4) & 255`，`追加次数候选 = raw & 15`。百分比除以10，其余已知固定属性除以100。小数精度、界面取整和追加次数属于观测解释，不作为官方协议保证；未知编号保留原值。

稀有度仅对截图确认过的配置编号提供默认值，不从未知编号的数字结构猜测。初始副属性条数只采用明确的0级记录或手工校正，不把满级当前条数当作初始条数。其余显示“未知”，可筛选未知项；选中源器后点击“校正分类”或双击源器，填写该 UID 的分类信息。手工记录单独保存，不改写网络原值，也不会被强化覆盖。分类信息包含在数据库备份中。

不上传原始抓包、账号凭据或个人库存到代码仓库；回归测试只使用合成消息。

## 本版行为

- 协议A/B与己方身份分开；本人方向须有证据或逐场确认，不默认A。
- 结算只关联同一连接、时间和上下文一致且无歧义的当前开场；未知、无关联或冲突结果保持未知。382／383目前只保留原码与旧诊断候选，不作为已证实的胜方。
- 本场胜方校正独立保存，可撤销；界面、历史、统计和导出使用同一结果。
- 普通回放／观战不计本人统计；自己的回放须明确确认本人、己方和分类。未确认胜负不当作失败。
- 点击角色名继续维护精确ID名称；皮肤ID单独维护。本场配装修正、历史连续浏览、多选删除／恢复、库存与导出保留。

## Windows便携EXE目录包

build_portable.py使用原生WinAPI GUI启动器（portable_launcher.c）和独立Windows运行库；输入固定为Python3.14.8嵌入式amd64 ZIP、PySide6-Essentials6.12.0及Shiboken6.12.0的Windows轮子，核对官方SHA256。构建工具为Zig0.14.1与pefile，仅构建端使用。DLL按QtCore/Gui/Widgets及图像、平台、样式插件的依赖闭包收取，不包含Qt开发工具或无关QML模块。

接收者完整解压后运行EtheriaAssistant.exe，保留_internal；无需安装Python，不会写入系统Python环境。实际程序、图片和映射按明确依赖收取，原始数据与分析证据不入包。原生启动器转发参数与退出码，不调用shell，不申请管理员权限。Python早期异常写入本机startup-error.log。

已生成并检查2.10.0便携包：Windows x64 GUI PE、ZIP CRC、逐文件SHA256、运行资源与隐私排除均通过；打包后的源码和资源在维护主机Qt上启动检查通过。当前环境无法启动Wine服务，Windows原生DLL与网卡运行仍未实机验证。目录包不是单独一个可任意拷走的EXE。

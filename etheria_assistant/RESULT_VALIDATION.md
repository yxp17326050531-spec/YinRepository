# 协议胜方与本人结果（2.7.1）

用户提供B方本人失败但382被显示胜利的反向记录，推翻固定A假设。当前0x6004 field1按382=A胜、383=B胜解释，再按独立确认的己方方向转换本人结果。382的反向解释有新样本支持，其他模式与结果码不扩展。己方未确认时只报告协议胜方，禁止默认本人胜负。

实时解析按捕获连接分别维护当前开场，结算只关联完整、无歧义且时间不早于开场的记录。新观测保存本地记录ID及精确开场时间；入库再次精确匹配，兼容旧观测的同来源、精确开场时间和唯一对局校验。本地记录ID不能作为已确认的协议对局ID，连接别名也不能跨抓包识别同一连接。

无关联、其他代码、重叠/重复开场歧义或相互冲突的已知结算保留未知。开场解析失败、流缺口和断开后不再关联旧场；场景边界后仍可等待同连接结算。回放/观战场景不推断本人胜负，也不计本人统计。原始 body_hex 保留在本地结算观测中用于追查；读取诊断不导出它，不会用积分变化猜测。

自动结算优先，旧手动记录只为兼容保留。界面不提供手动胜负入口；可确认本场己方A/B，原始协议阵容和结算保持不变。完整属性/效果指纹匹配仅为本地推定，不是账号验证。旧版观测在启动时重放补录，不重新抓包。关联不到的记录继续未知。


2.7.1：观战的协议胜方单独保留，不能转换成本人胜负。玩家方向可由同连接确认选人、玩家资料和上场阵容交叉关联；记住本号须用户明确选择，后续身份匹配优先于阵容指纹。昵称、玩家列表顺序及先手不能直接确定己方。开场与结算上下文标记均存在时须一致；存储再次校验连接。缺少证据或发生冲突时保持未知。新增测试只使用合成协议数据。

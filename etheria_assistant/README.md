# 伊瑟 · 对局助手 2.5.1

源码持续维护于 `yxp17326050531-spec/YinRepository` 的 `main` 分支。首次用 `setup_git.cmd` 安装到 Git 工作目录，之后通过 `update.cmd` 增量更新。

本机运行的 PySide6 对局助手。界面按 B 预览调整为蓝黑底、青色强调、蓝/红双方标题、黄色速度和紧凑角色行；窄窗口上下排列队伍。

## 一次安装，以后增量更新

下载仓库中的 `etheria_assistant/setup_git.cmd` 并双击。需要 Git for Windows、Python 3.10+ 和私有仓库访问权限；Git 首次访问可能打开浏览器登录 GitHub。脚本只克隆 `main` 分支，并在 `checkout/etheria_assistant` 内安装依赖。

安装完成后：

- 启动：`checkout/etheria_assistant/start.cmd`。
- 更新：先关闭程序，双击同目录 `update.cmd`，完成后再启动。
- 日常更新只拉取改动；依赖未变化就不重复安装；有新提交时自动运行本机回归测试。
- 源码有本地改动或 Git 历史分叉时停止更新，保留现有文件。更新不会自动解决冲突。
- 程序和更新器共用锁，防止本版运行期间修改源码。升级旧版前仍需自己关闭旧程序。

若是直接下载的源码目录，可先运行 `install_windows.cmd` 和 `start.cmd`；这种非 Git 目录不能增量更新。推荐通过 `setup_git.cmd` 安装一次。

## 已用旧分支安装的电脑

关闭程序，在 `checkout` 目录打开终端，依次执行以下命令，把已有安装切换为跟踪主分支（无需重新安装）：

```bat
git remote set-branches origin main
git fetch origin
git switch main
git branch --set-upstream-to=origin/main main
etheria_assistant\update.cmd
```

如果切换因本地改动而停止，先保存或提交改动再重试；不要强制覆盖。数据库和用户名称映射仍沿用原位置。

## 按属性排序（2.5.1）

“源器与配装”新增排序栏：选择速度、生命/攻击/防御及百分比、暴击率、暴击伤害、效果命中/抵抗或等级，切换从高到低或从低到高。属性可按副属性、主属性或主副属性合计比较，条件会记住；默认顺序不改变原列表顺序。

排序采用解码小数数值，例如三件游戏均显示16速的源器会按16.2、15.9、15.6排列。缺少所选属性的装备在两个方向都排在末尾，同值按UID稳定排列。排序可以与分类筛选和搜索组合，选中的UID在重新排列后继续保留。排序值列会显示实际比较数值。

源器模块到此阶段收尾；保留已有实时更新，暂不扩展强化分析。后续开发优先对局数据读取。

## 实时强化与分类筛选（2.5.0）

在“源器与配装”开始监听后，强化过程中的属性与等级会自动同步，不需要每次重新登录。首次最好在登录前开始监听，以取得完整背包；中途开始监听也能接收强化，但没观测到的矩阵等字段保持未知。重新开始监听会沿用已保存资料，未收到的变更无法反映。

强化属性消息 `0x1132` 按 UID 合并已有字段；`0x1134` 补充等级，不覆盖未下发的矩阵或锁定原值。不同内容保存为库存快照；同一网络分组里多次变化也按处理顺序保留。导入强化抓包只使用采集时间之前的已存库存作基础，避免用未来状态污染旧记录。

点击“分类筛选”组合矩阵、矩阵点数、稀有度、初始副属性条数、主属性与副属性。同一类别可多选，副属性要求同时具备，不同类别同时生效。筛选条件会记住；“清除筛选”同时清空文字搜索。选中装备后，实时更新尽量保留同一 UID 的选择，详情可继续查看原始 JSON。

属性按已对照样本拆分：`数值 = raw >> 12`，`属性编号 = (raw >> 4) & 255`，`追加次数候选 = raw & 15`。百分比除以10，其余已知固定属性除以100。小数精度、界面取整和追加次数属于观测解释，不作为官方协议保证；未知编号保留原值。

稀有度仅对截图确认过的配置编号提供默认值，不从未知编号的数字结构猜测。初始副属性条数只采用明确的0级记录或手工校正，不把满级当前条数当作初始条数。其余显示“未知”，可筛选未知项；选中源器后点击“校正分类”或双击源器，填写该 UID 的分类信息。手工记录单独保存，不改写网络原值，也不会被强化覆盖。分类信息包含在数据库备份中。

不上传原始抓包、账号凭据或个人库存到代码仓库；回归测试只使用合成消息。

## 本版行为

- A 固定为己方，B 固定为敌方；界面显示“己方 / 敌方”。
- 0x6004 结算 field 1：382=己方胜利、383=己方失败。只关联同来源、精确开场时间的当前对局；未知、无关联或冲突结算保持未知。
- 自动结果存入 SQLite，实时界面、历史、统计和导出统一读取；旧版保存的可关联结算也会重放补录。
- 删除手动胜负、敌我选择；“对局分类”只维护模式与赛季。已有旧手动记录保留，自动结算优先。
- 对位与搭配总览使用己方 A 的样本；完整统计默认己方，可切换双方。
- 点击角色名继续维护精确 ID 名称；皮肤 ID 单独维护。本场配装修正、映射、历史多选删除/恢复、库存与导出保留。

对局类型仍由用户分类；未知结算不当作失败。现有结算代码适用已确认的样本，不猜测其他代码、退赛、断线或平局。矩阵显示观测到的效果，不能推算完整点数。

## 数据

沿用 `%LOCALAPPDATA%\EtheriaAssistant\history.sqlite3`、用户映射和日志，与源码目录分开。更新、重新克隆不会删除它们。Wireshark/dumpcap 与 Npcap 沿用本机安装，不重复下载驱动。统计来自本地观测，不是全服数据。

`UI_PREVIEW.png` 是本版程序离屏运行截图（示例数据），不是生成式设计图。当前没有游戏角色头像资源。
